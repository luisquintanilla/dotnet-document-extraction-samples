What is a token?
A language model never sees your text directly. Before the model runs, a tokenizer splits the text into small pieces called tokens, and then maps each piece to an integer called a token ID. The model works only with those numbers.
When the model answers, the process runs in reverse. The model produces token IDs, and the tokenizer decodes them back into text you can read.

Why not just use words?
Splitting on words sounds simple, but English alone has hundreds of thousands of words, and rare words end up as "unknown." Splitting into single characters fixes that, but it makes every sequence very long. Modern models use subword tokens instead. Common words stay whole, and rare words break into reusable pieces, such as "token" plus "ization." Vocabularies stay in the tens or hundreds of thousands of entries.
Three things to remember
•A token is not a word. A token often includes its leading space, so " world" is a single token.
• Every model has its own tokenizer. Use the one the model was trained with. • Character counts are a poor guess. Always count tokens with the tokenizer.

Counting tokens and staying in budget
Every model has a context window, the maximum number of tokens it can read and write in one request. GPT-4o, for example, has a 128K token window. You are also billed per token, so counting tokens helps you control both size and cost.
Cut text at a token limit
Cutting a string at 1,000 characters might give you 200 tokens or 800 tokens. Use GetIndexByTokenCount instead. It returns the character index where your token budget runs out, so you can slice the text safely.
int maxTokens = 500;
if (tokenizer.CountTokens(longText) > maxTokens)
int cut = tokenizer.GetIndexByTokenCount( longText, maxTokens, out _, out int used);
longText = longText[..cut]; Console.WriteLine($"Kept {used) tokens.");
To keep the most recent text instead, such as the end of a chat history, use GetIndexByTokenCountFromEnd and slice with text[cut.. ].
